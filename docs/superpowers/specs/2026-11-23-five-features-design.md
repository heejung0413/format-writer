# 기능 5가지 추가 설계

- 작성일: 2026-11-23
- 상태: 설계 승인됨
- 기반 문서: `2026-11-23-format-writer-design.md`

업무용 기본 포맷, 결과 직접 편집, 길이 옵션, 서명 저장, 단축키를 추가한다. 기존 동작과 저장된 데이터는 그대로 쓸 수 있어야 한다.

## 1. 업무용 기본 포맷

`lib/defaults.ts`의 `DEFAULT_FORMATS`에 네 개를 더해 일곱 개로 만든다. 순서는 메일, 채팅, 보고, Jira 코멘트, MR 본문, 리뷰 답글, 주간 보고다.

| id | 이름 | 지시문의 요지 |
|---|---|---|
| `jira` | Jira 코멘트 | `ㅁ 문제 원인`, `ㅁ 수정 내용`, `ㅁ 테스트 결과`, `ㅁ 확인 요청` 소제목 순서로 쓴다. 내용이 없는 소제목은 뺀다. 각 항목은 짧은 문장이나 번호 목록으로 쓴다. 인사말과 맺음말을 넣지 않는다. |
| `mr` | MR 본문 | `## 관련 이슈`, `## 변경 내용`, `## 결과`, `## 테스트`, `## 확인 요청` 마크다운 소제목으로 쓴다. 변경 내용은 번호 목록으로, 결과는 바뀌기 전과 후를 나란히 적는다. 입력에 없는 항목은 뺀다. |
| `review` | 리뷰 답글 | 코드 리뷰 댓글에 다는 답글이다. 첫 문장에 결론(무엇을 어떻게 했는지)을 쓰고, 근거를 한두 문장 덧붙인다. 전체 두세 문단을 넘기지 않는다. 인사말과 맺음말을 넣지 않는다. |
| `weekly` | 주간 보고 | `금주 진행 내용`과 `차주 진행 예정` 두 묶음으로 나눠 각각 불릿 서너 개로 쓴다. 불릿 한 줄은 40자 안팎으로 짧게 쓴다. |

지시문은 일반적인 형태로만 쓴다. 저장소가 공개이므로 특정 회사의 규칙, 이름, 티켓 번호를 넣지 않는다.

### 이미 쓰고 있는 데이터

`data/formats.json`이 이미 있으면 새 기본 포맷을 자동으로 넣지 않는다. 사용자가 지운 포맷이 되살아나면 안 되기 때문이다.

- `lib/store.ts`에 `restoreDefaultFormats()`를 추가한다. 현재 목록에 없는 id의 기본 포맷만 목록 끝에 붙이고 `{ formats, added }`를 돌려준다. `added`는 추가한 개수다.
- `POST /api/formats/defaults`가 이 함수를 부르고 `{ formats, added }`를 돌려준다. 요청 본문은 받지 않는다. 다른 POST와 같이 `Content-Type: application/json`이 아니면 415로 거절한다.
- 포맷 관리 모달에 "기본 포맷 불러오기" 버튼을 둔다. 누르면 목록을 갱신하고 "기본 포맷 N개를 추가했습니다." 또는 "추가할 기본 포맷이 없습니다."를 표시한다.

이름이 같아도 id가 다르면 다른 포맷으로 본다.

## 2. 결과 직접 편집

- 결과 칸을 여러 줄 입력 칸(`textarea`, 접근성 이름 "결과")으로 바꾼다. 작성 중(`busy`)에는 읽기 전용이고, 끝나면 편집할 수 있다. 결과가 없을 때는 지금처럼 안내 문구만 보인다.
- 사용자가 고치면 화면의 결과가 바로 바뀌고, 대화 기록(`messages`)의 마지막 assistant 메시지도 고친 글로 바뀐다. 그래서 다듬기는 고친 글을 기준으로 하고 복사도 고친 글을 복사한다.
- 기록 id가 있으면 마지막 입력 뒤 1초가 지났을 때 `PATCH /api/history/[id]`로 `output`을 저장한다. 저장이 끝나면 결과 칸 아래에 "저장됨"을 표시하고, 다시 고치기 시작하면 지운다. 저장에 실패하면 "저장하지 못했습니다."를 표시한다.
- 고친 글이 공백뿐이면 저장하지 않는다.
- 기록 id가 없으면(첫 생성을 중단한 경우) 편집은 되지만 저장하지 않는다.
- 저장을 기다리는 중에 다른 기록을 열거나 새로 작성하거나 다듬기를 시작하면, 기다리던 저장을 그 자리에서 먼저 보낸다. 고친 글이 다른 기록에 덮어쓰이거나 사라지면 안 된다.

## 3. 길이 옵션

- `lib/defaults.ts`에 `LENGTHS = ["짧게", "보통", "자세히"]`를 추가한다. 기본값은 "보통"이다.
- 옵션 바에 "길이" 선택을 말투 옆에 둔다.
- `POST /api/generate` 본문에 `length`를 받는다. 목록에 없으면 "보통"으로 바꾼다.
- 지시문(`lib/prompt.ts`)에 길이 줄을 넣는다. "보통"일 때는 줄을 넣지 않는다.
  - 짧게: 핵심만 남겨 가능한 한 짧게 쓴다.
  - 자세히: 배경과 이유까지 풀어서 자세히 쓴다.
- `HistoryItem`에 선택 필드 `length`를 추가한다. `POST /api/history`는 `length`가 문자열이면 저장하고 없으면 저장하지 않는다. 기록을 복원할 때 `length`가 없으면 "보통"으로 본다.

## 4. 서명 저장

- 설정은 `data/settings.json`에 객체 하나로 저장한다. 지금은 `{ "signature": string }`뿐이다.
- `lib/store.ts`에 `getSettings()`, `saveSettings()`를 추가한다. 목록 파일과 같은 규칙을 따른다: 한 번에 하나씩 처리, 원자적 저장, 파일이 없으면 `{ signature: "" }`, 깨졌거나 객체가 아니면 `.broken-<시각>`으로 옮기고 기본값으로 시작.
- `GET /api/settings`는 설정을 돌려준다. `PUT /api/settings`는 `{ signature }`를 받아 저장한다. 서명은 앞뒤 공백을 지우고, 문자열이 아니거나 500자를 넘으면 400으로 거절한다.
- 화면 상단에 "설정" 버튼을 두고, 모달에서 서명을 여러 줄로 입력해 저장한다. 저장하면 모달을 닫는다.
- 서명은 브라우저가 생성 요청에 실어 보내지 않는다. `POST /api/generate`가 서버에서 설정을 읽어 지시문에 넣는다.
- 지시문에는 서명이 있을 때만 다음을 넣는다: 맺음에 보내는 사람 서명이 들어가는 글이면 아래 서명을 그대로 쓰고, 서명이 어울리지 않는 글(메신저 글, 코멘트, 보고)에는 넣지 않는다. 서명은 `<서명>` 태그로 감싼다.

## 5. 단축키

- `⌘ + Enter`(Windows·Linux는 `Ctrl + Enter`): 작성하기. 내용이 있고 포맷이 선택돼 있고 작성 중이 아닐 때만 동작한다. 화면 어디에 포커스가 있어도 동작한다. 단, 모달이 열려 있으면 동작하지 않는다.
- `⌘ + Shift + C`(`Ctrl + Shift + C`): 결과 복사. 결과가 있고 작성 중이 아닐 때만 동작하고, 브라우저 기본 동작을 막는다. 복사 버튼을 눌렀을 때와 같이 "복사됨"을 표시한다.
- 다듬기 입력 칸의 Enter 동작(한글 조합 중 제외)은 그대로 둔다.
- 작성하기 버튼과 복사 버튼에 단축키를 작게 표시한다. 버튼의 접근성 이름은 "작성하기", "복사" 그대로 둔다(단축키 표시는 `aria-hidden`).

## 6. 데이터 호환

- 기존 `formats.json`, `history.json`은 고치지 않고 그대로 읽는다.
- `settings.json`이 없어도 모든 기능이 동작한다.

## 7. 테스트

- 유닛: 지시문의 길이·서명 줄, 저장소의 기본 포맷 복원과 설정 읽기·쓰기, 새 API 라우트의 검증, 각 컴포넌트의 새 동작, 페이지의 편집·자동 저장·단축키.
- 통합: 길이와 서명이 가짜 Claude 프로세스의 지시문에 들어가는지, 고친 글이 기록 파일에 저장되고 다듬기에 쓰이는지, 기본 포맷 불러오기가 파일에 반영되는지.
- E2E: 기능마다 한두 개. 편집 후 새로고침해도 고친 글이 남는지, 단축키로 작성·복사가 되는지, 서명을 저장한 뒤 메일에 들어가는지(가짜 Claude가 지시문의 서명을 결과에 되돌려 줌), 길이 선택이 전달되는지, 기본 포맷 불러오기.
- 기존 테스트는 동작이 바뀐 곳만 고친다(기본 포맷 개수, 결과 칸이 `pre`에서 `textarea`로 바뀐 부분).

## 8. 넣지 않는 것

받는 사람·말투·길이 목록 편집, 포맷별 서명, 편집 이력 되돌리기, 단축키 변경.
